# 试点二（中）：LDPC2 接口参数边界校验

> 状态：草案 v0.1，待确认；确认前不作为正式 Spec 输入。
> 基线：cuphy 快照 `4f65f97c`（公开代码）。

## 1. 背景与目标

`error_correction/ldpc2` 相关接口在参数非法时行为不明确，存在越界风险。目标：为对外接口补齐参数校验与错误返回，覆盖 2～3 个模块。

## 2. 需求

### R1（必须）空指针与长度校验

对外接口收到空指针或零长度输入时，返回明确的错误码，不进入计算路径。

验收标准：

- 空输入返回既定错误码，且不写任何输出缓冲；
- 零长度输入返回错误码，不读取无效地址；
- 合法输入行为与改动前完全一致。

### R2（必须）配置参数合法性校验

码率、块长等配置参数越界时，在初始化阶段返回错误，不进入解码循环。

验收标准：

- 每个可配置参数至少覆盖下界、上界与越界三类用例；
- 错误码可区分「参数越界」与「不支持的组合」。

### R3（必须）调用方错误处理

调用方必须检查返回码并向调用链上层传播，不得吞掉错误。

验收标准：

- 反向调用方逐一定位（S13）；
- 至少一个上层调用路径有错误传播测试。

## 3. 非功能需求

- N1：校验只增加常数级开销，不改变合法输入的吞吐基准。
- N2：新增错误码不得与既有错误码冲突。

## 4. 范围外

- 不重构解码算法；
- 不改变对外 ABI 的既有函数签名（只增加错误返回路径）。

## 5. 开放问题

- Q1：现有错误码体系的具体取值范围待 S13 影响分析确认。
- Q2：是否所有入口都需要校验，还是只覆盖公开 API，需模块负责人确认。
