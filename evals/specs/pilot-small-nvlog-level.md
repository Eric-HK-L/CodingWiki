# 试点一（小）：新增日志级别配置项

> 状态：草案 v0.1，待确认；确认前不作为正式 Spec 输入。
> 基线：cuphy 快照 `4f65f97c`（公开代码）。

## 1. 背景与目标

cuphy 调试时日志噪声大，需要在不重新编译的前提下调整日志级别。目标：新增一个配置项，并在启动时校验取值。

## 2. 需求

### R1（必须）新增日志级别配置项

配置文件中新增 `log_level`，取值 `error` / `warn` / `info` / `debug`，默认 `info`。

验收标准：

- 未配置时行为等同于 `info`；
- 非法取值导致启动失败，错误信息包含字段名与合法取值；
- 变更后无需重新编译。

### R2（必须）配置项文档化

在仓库配置说明中补充该配置项的用途、默认值与取值范围。

验收标准：

- 配置说明可检索到该字段；
- 与代码中的默认值一致。

## 3. 非功能需求

- N1：不得影响现有构建目标与启动耗时（启动阶段只做一次字符串校验）。
- N2：非法取值不得导致越界或未定义行为。

## 4. 范围外

- 不支持运行期热切换（重启生效）；
- 不改变现有日志格式。

## 5. 开放问题

- Q1：配置项归属的配置文件由影响分析确认后填写（S13）。
- Q2：是否需要环境变量覆盖，待需求提出人确认。
