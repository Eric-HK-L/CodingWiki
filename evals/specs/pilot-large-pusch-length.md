# 试点三（大）：PUSCH 解码输入长度边界检查

> 状态：草案 v0.1，待确认；确认前不作为正式 Spec 输入。
> 基线：cuphy 快照 `4f65f97c`（公开代码）。

## 1. 背景与目标

PUSCH 解码入口对输入长度的约束依赖调用方自觉，超长输入可能造成越界读写。目标：在流程入口建立统一长度校验，并把错误沿流程传播到可见的返回点，涉及多个模块与数据结构。

## 2. 需求

### R1（必须）入口长度校验

在 PUSCH 解码流程入口校验输入长度与输出缓冲容量，超限时立即返回错误，不进入任何子步骤。

验收标准：

- 长度为 0：返回 `ERR_INVALID_LEN`；
- 长度超过输出缓冲：返回 `ERR_BUFFER_TOO_SMALL`；
- 边界值（恰好等于容量）正常处理，不发生越界写。

### R2（必须）错误传播

错误码沿调用链逐层返回，不得被中间层覆盖为成功；上层可区分「长度非法」与「内部解码失败」。

验收标准：

- 至少一条跨 2 层以上的调用路径有错误传播测试；
- 日志记录错误码与输入长度，不记录缓冲区内容。

### R3（应该）配置与文档同步

若长度上限来自配置项，需在配置说明中写明单位、默认值与上限来源。

验收标准：

- 配置说明与代码默认值一致；
- 影响分析列出所有读取该配置的位置。

### R4（可选）诊断信息

错误返回时可附带最小诊断信息（长度、容量），但不得包含用户数据内容。

验收标准：

- 诊断信息只含元数据；
- 可通过开关关闭。

## 3. 非功能需求

- N1：合法输入路径不得引入额外内存拷贝。
- N2：校验失败路径不得部分写入输出缓冲。
- N3：错误码与既有接口兼容，不改变 ABI。

## 4. 范围外

- 不修改解码算法与 GPU kernel 实现；
- 不做性能优化。

## 5. 开放问题

- Q1：输出缓冲容量由调用方传入还是内部推导，需架构师确认。
- Q2：`ERR_INVALID_LEN` / `ERR_BUFFER_TOO_SMALL` 是否已有定义，待 S13 核实。
- Q3：「较大功能」的验收环境是否覆盖 CPU 仿真路径，需测试负责人确认。
