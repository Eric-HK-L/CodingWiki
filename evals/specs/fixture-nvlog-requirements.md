## 1. 背景与目标

cuphy 的日志输出目前使用固定级别，调试时噪声过多。希望日志级别可以通过配置调整，无需重新编译。

## 2. 功能需求

### 2.1 配置项

在仓库配置中新增日志级别配置项，取值限定为 `error`、`warn`、`info`、`debug` 四档，默认 `info`。

验收标准：

- 未配置该项时，行为与 `info` 一致；
- 配置为非法字符串时，程序启动失败并给出可读错误；
- 配置为 `debug` 时，debug 级日志可见。

### 2.2 运行期覆盖

允许通过环境变量覆盖配置文件的日志级别，环境变量优先。

验收标准：

- 环境变量合法时生效；
- 环境变量非法时，忽略覆盖并记录一条警告，不改变配置文件的值。

### 2.3 性能

日志级别为 `error` 时，日志调用不得带来可感知的性能下降，**尽量低延迟**。

代码如下，注意围栏内的 `#` 不是标题：


## 3. 非功能需求

- 配置项变更不得影响现有构建目标；
- 日志级别切换不需要重新编译；
- 错误信息不得泄露内部文件路径以外的敏感信息。

## 4. 开放问题
