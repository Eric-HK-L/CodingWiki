## 1. 范围与设计原则

### 1.1 范围

| 侧 | 内容 | 对应优化方案 |
|---|---|---|
| Wiki v2 | 模块三信号聚类、页面体系 v2（architecture / flow-detail / concept）、图示体系、人工干预保护与回同步、页面引用图谱、证据级增量、wiki_plan.yaml、站点升级（Pagefind/导航/双语摘要） | §3.1–§3.7 |
| RAG v2 | 切块 v2（上下文头 + AST 边界）、ANN + 增量索引、查询理解（符号直达/术语改写/多查询扩展）、拒答 v2、评测扩容与标定工具化、知识卡片、问答延伸阅读 | §4.1–§4.6 |

### 1.2 地基保留清单（优化不触碰的既有资产）

以下机制为已验证地基，优化阶段**只复用、不重构**：

1. 快照绑定与 blob 内容寻址（一切产物绑定 `<repo>@<rev>`）；
2. 事实层与出处机械校验（`verify/` 只读原则、证据 E 编号、quote 精确匹配）；
3. 发布门禁 + `current` 原子切换 + 草稿哈希一致性（`domain/wiki.py` 发布门禁）；
4. `PageDeps` 增量复用框架（S17，本文仅细化到证据级）；
5. `ModelBackend` / `TaskPacket` / `BackendResult` 契约与修复循环（≤3 轮）；
6. `SearchFilters` 候选级生效语义、RRF 融合、reranker 候选池结构；
7. JobRunner 六阶段编排与 per-repo 锁；
8. MockBackend 质量地板与故障注入测试模式。

### 1.3 设计原则

1. **增量落于接口缝**：全部改动属于总体架构 §6「允许演进」类（PageType 取值、SearchFilters 字段、Chunk 附加文本、IndexMeta 附加字段、PageDeps 附加字段），无冻结项变更；
2. **确定性兜底**：凡模型草拟产物（架构图、时序图、概念页），必须有确定性校验与确定性降级产物，模型缺席时 MockBackend 路径仍过全部校验；
3. **可选依赖不破坏零依赖可跑**：hnswlib、Pagefind 均为可选；缺失时回落暴力检索 / search.js 前端过滤，行为正确仅能力降级；
4. **人工内容优先于机器内容**：再生成与人工段冲突时，宁保留人工段报错也不静默覆盖；
5. **默认关的成本开关**：多查询扩展、双语摘要等 token 增量全部开关化，默认关。

## 3. 数据模型增量（domain/，纯 Pydantic，无 I/O）

全部继承统一基类（`extra="forbid"` + `frozen=True` + 空白规范化）。以下为框架级 schema 要点，字段级定义在各小阶段开工时随代码评审定稿。

### 3.1 ModuleMap（`domain/module_map.py`，S37）

```text
ModuleMap{repo_id, snapshot_id, cluster_version, seed, entries: list[ModuleEntry], collaborations: list[ModulePair]}
ModuleEntry{module_key, layer: str|None, files: list[str], build_targets: list[str],
            cohesion_score, source_signals: list[Literal["dir","build","call"]]}
ModulePair{a: module_key, b: module_key, call_density}        # 协作模块互链
```

不变量：`entries` 的 files 并集 == facts 在范围文件集，交集为空（归属唯一性，校验规则保证）；`cluster_version` 随算法变更递增（同 facts 的 `EXTRACTOR_VERSION` 机制）。

### 3.2 页面体系 v2（`domain/wiki.py` 扩展，S37/S39）

- `PageType` 新增取值：`architecture` / `flow_detail` / `concept`（允许演进类，既有 12 种不变）；
- `PageMeta` 新增可选块：

```text
protection: {mode: generated|supplemented|rewritten, human_sections: list[str], human_sha256: str|None}
```

- `PageDeps` 新增 `evidence_refs: list[str]`（页面引用的 E 编号对应的 `file:line` 符号集），与作用域级 `files` 并存；
- `PageStatus` 不变；人工段引用出处失效时页面正文标记 `stale-section`（内容标记，非状态机新值）。

### 3.3 WikiGraph（`domain/graph.py`，S38/S40）

```text
GraphDoc{page_id, kind: module_deps|architecture|sequence, mermaid: str, source: deterministic|model,
         nodes: list[str], edges: list[tuple[str,str]]}      # 校验输入
WikiGraph{pages: dict[page_id, {links_out, links_in, kind}], modules: dict[module_key, {pages, deps}]}
```

GraphDoc 落盘于 drafts，是校验对象；WikiGraph 落盘于版本目录，是站点导航与「引用本页」的数据源。

### 3.4 KnowledgeCard（`domain/card.py`，S44）

```text
KnowledgeCard{module_key, snapshot_id, one_liner, key_types: list[{name, file, line}],
              entry_points: list[{symbol, signature}], deps: list[str], deps_by: list[str],
              terms: list[str], page_id}
```

体积预算 ≤ 2KB/张（序列化 JSON 计）；双格式落盘（JSON 权威 + Markdown 渲染）。

### 3.5 WikiPlanConfig（`domain/wiki_plan.py`，S40）

```text
WikiPlanConfig{pages: list[WikiPlanPage], notes: list[str], template: str,
               languages: list[Literal["zh","en"]], full_bilingual: bool=false}
WikiPlanPage{page: str, goal: str, hints: list[str], scope: list[str], parent: str|None}
```

加载走 `config/wiki_plan.py`（StrictLoader 复用）；缺文件 = 空白名单，规划器纯确定性补齐。

### 3.6 RAG 模型扩展（`domain/rag.py`，S41/S42/S43）

```text
Chunk        新增 context_header: str          # module/file/symbol 面包屑；只进嵌入与 BM25，不进引用显示
IndexMeta    新增 ann: {kind: hnsw, params: {M, ef}, count} | None
CalibrationProfile{repo_id, golden_set, vector_threshold, rerank_threshold, symbol_direct: bool,
                   calibrated_at, report_ref}   # 标定产物，写仓库配置引用
RefusalPolicy{mode: legacy|v2}                  # v2 = 三信号 AND；legacy 保留供回归对比
QueryPlan    【新】{original, rewritten: list[str], direct_symbols: list[str], expanded: bool}
```

## 4. 接口协议签名（框架级）

### 4.1 Wiki 侧

```python
# generate/cluster.py（S37）
class ModuleClusterer(Protocol):
    def cluster(self, facts: RepoFacts, snapshot: Snapshot) -> ModuleMap: ...
    # 实现：确定性（固定种子 Louvain 或标签传播）；同输入同输出

# generate/graphs.py（S38）
class GraphBuilder(Protocol):
    def module_deps(self, module_map: ModuleMap, facts: RepoFacts) -> GraphDoc: ...        # 确定性
    def assemble_model_graph(self, task_output: Path, kind: str) -> GraphDoc: ...          # 模型草拟装配

# publish/merge.py（S39）
class PageMerger(Protocol):
    def merge(self, old_page: Page, new_draft: Page) -> Page: ...
    # human_sections 原样保留；合并后人工段哈希 ≠ human_sha256 即抛 ContentIssue
    def sync_back(self, page: Page, external_md: str) -> Page: ...   # 导出 md 的外部改动并入 human_sections

# publish/graph.py（S40）
class WikiGraphBuilder(Protocol):
    def build(self, pages: list[Page], module_map: ModuleMap) -> WikiGraph: ...

# publish/cards.py（S44）
class CardBuilder(Protocol):
    def build(self, module: ModuleEntry, facts: RepoFacts, pages: list[Page]) -> KnowledgeCard: ...
```

### 4.2 RAG 侧

```python
# retrieval/query.py（S42）
class QueryUnderstanding(Protocol):
    def analyze(self, query: str, facts_index: FactIndex, terms: list[str]) -> QueryPlan: ...
    # L1/L2 确定性必做；L3 模型扩展由 --expand 启用，不经本协议（由 answer/search 编排）

# retrieval/ann.py（S41）
class AnnIndex(Protocol):
    def build(self, vectors: list[list[float]]) -> None: ...
    def add(self, label: int, vector: list[float]) -> None: ...
    def mark_deleted(self, label: int) -> None: ...
    def search(self, vector: list[float], k: int) -> list[tuple[int, float]]: ...   # (label, dist)
    def save(self, path: Path) -> None: ...
    def load(self, path: Path) -> None: ...

# eval/calibrate.py（S43）
class ThresholdCalibrator(Protocol):
    def calibrate(self, report: EvalReport) -> CalibrationProfile: ...
```

`HybridSearcher.search(query, filters, top_k)` 签名不变；内部改为消费 `QueryPlan` 与 ANN。
**top_k 语义不变**：过滤后空间内的 top_k（回归测试锁死）。filters 非空时 ANN 路
overfetch ×4 → 按 allowed 集过滤 → 不足则递增 overfetch 重试一轮 → 仍不足如实返回。

## 6. 校验与门禁增量

### 6.1 发布门禁（在既有五项上追加）

| 新增门禁 | 判定 |
|---|---|
| 图谱一致性 | graph.json 的 links_out 全集 ⊆ 版本内页面集（复用 broken_internal_link 数据，不重复解析） |
| 卡片体积 | 每张 KnowledgeCard ≤ 2KB |
| 图产物完整 | 版本内页面对应的 GraphDoc 全部通过校验且随版本落盘 |

### 6.2 verify/ 新增规则（校验器只读原则不变）

| 规则 | 组 | 判定 | 严重级 |
|---|---|---|---|
| `module_membership_unique` | 结构 | ModuleMap 归属唯一性不变量 | error |
| `graph_node_exists` | 图 | 图节点解析到快照内符号/模块 | error |
| `graph_edge_grounded` | 图 | 模型草拟边在 facts 调用边闭包内（限深默认 4） | error |
| `graph_renderable` | 图 | Mermaid 可被确定性 parser 解析 | error |
| `graph_acyclic_layers` | 图 | 架构层间依赖无环 | warning（提示架构问题，不阻断） |
| `flow_step_order` | 语义 | flow-detail 步骤顺序不与调用事实矛盾 | error |
| `human_section_preserved` | 证据 | 重生成后人工段逐字存在、哈希一致 | error |
| `protection_mode_legal` | 结构 | protection.mode 三值枚举合法 | error |

### 6.3 评测门禁（S43 落地，S41/S42 即开始记录）

MRR / nDCG 纳入回归门禁：相对基线回退 >3pp 阻断发布；ANN vs exact 每版双跑，召回损失 >1% 构建失败。cuphy-v2 修正目标：MRR ≥ 85%、nDCG ≥ 65%（基线 72.6% / 48.0%）。

## 7. 与既有机制的集成点

### 7.1 证据级增量（S39，PageDeps 二级判定）

```text
变更文件集 Δfiles（快照 diff，既有）
  → 一级判定：Δfiles ∩ deps.files ≠ ∅ 的页面候选（既有逻辑）
  → 二级判定【新】：候选页的 evidence_refs 涉及符号签名未变 且 人工段未引用变更点 → 复用
  → 复用页仍刷新 front matter snapshot 字段（内容逐字节不变，仅元信息前移）
```

### 7.2 再生成三向合并（S39，接入 generate/pipeline.py）

```text
重生成某页 → 取草稿区旧页（含 protection 块）+ 新模型草稿
  → publish/merge.py 按规范化标题章节对齐（精确匹配，不模糊）
  → human_sections 原样保留，其余章节用新草稿
  → human_section_preserved 校验；对齐失败的人工段整块追加页尾标 unmerged（宁多勿丢）
  → mode=rewrite 的页：仅刷新「出处」段链接与快照号，正文不动
```

### 7.3 JobRunner 六阶段不变，阶段内部挂接点

| 阶段 | 挂接 |
|---|---|
| facts | 不变 |
| wiki | plan 前跑 cluster（module_map.json 随快照哈希缓存复用）；generate 内嵌 merge；verify 含新规则 |
| publish | 追加 graph/cards/graphs 产物与 §6.1 门禁 |
| index | 增量构建 + ANN 产物；模型名绑定规则不变 |

### 7.4 MockBackend 义务扩展

MockBackend 须能产出：合规 GraphDoc（确定性模块依赖图降级产物）、带 protection 块的页面、概念页骨架——保证 CI 在无真实模型下覆盖全部新校验规则（质量地板原则不变）。

### 7.5 错误模型与退出码

不新增类别。人工段合并冲突、聚类不变量破坏 → 内容/输入错误（退出码 2）；hnswlib/Pagefind 缺失 → 环境错误（3）或静默降级（按 §1.3-3 原则，降级路径记日志）；ANN 构建失败 → 可重试（4）。标定工具输出不可复算 → 内部错误（1）。

## 9. 小阶段边界（S37–S44）

每阶段：独立分支 + PR；三层测试；开发记录七段式；质量门 ruff + mypy + pytest 全绿；
真实数据验证不可省（dry-run 不算验收证据）。

| 阶段 | 做 | 不做 | 验收硬判据 | 真实数据验证 | 依赖 |

## 14. S37 实施细节（模块三信号聚类 + 页面体系 v2）

> 本节为 S37 开工时的回写扩充（先设计再编码）。范围对齐 §9 表 S37 行。

### 14.1 ModuleMap 构建（`generate/cluster.py`）

`build_module_map(facts) -> ModuleMap`，纯函数、确定性（无随机、无时间、无外部输入）：

1. **目录边界（基础分区）**：复用 `modules.module_groups(facts)` 输出，目录是最外层边界，不被调用信号打破；
2. **构建拆分**：模块内文件按 `BuildTarget.sources` 归属分组；当 ≥2 个 target 组各含
   ≥ max(3, 模块文件数 × 20%) 个文件时拆子模块，子模块键 `<module>--<target>`；
   无 target 归属的文件留在基模块键下；
3. **调用协作**：跨模块已解析调用（`CallFact.targets` 命中符号索引）聚合成模块对，
   跨模块调用数 ≥ 5 且密度（调用数 / min(两侧文件数)）≥ 1.0 的模块对入 `collaborations`；
   （对应优化方案「社区发现」的确定性落地：目录边界不破的前提下，调用信号的产出物
   就是协作互链，不做重分区——这是相对方案文字的收窄，理由是 §3.1 合并规则第 1 条优先）；
4. **分层**：模块依赖有向边（任何已解析跨模块调用，方向 = 调用方 → 被调方）做 SCC 凝聚
   （Tarjan，按模块键字典序确定性遍历），在凝聚 DAG 上取最长路径深度，`layer = "L<depth>"`；
   环内模块同层；
5. **不变量**：全部 entry 的 files 恰好是 facts 在范围文件集的一个划分（构建后断言，
   违反抛内部错误）；`validate_module_map(mm, facts)` 供 CLI/测试复核——
   `module_membership_unique` 以此形式落地（它是 ModuleMap 属性而非页面属性，
   不进入 PageVerifier，§6.2 表相应以此为准）。

`ensure_module_map(facts, wiki_dir) -> ModuleMap`：`wiki/<repo>/module_map.json` 存在且
`snapshot_id` 一致则复用，否则重建并原子写盘。`pipeline/stages.py` wiki 阶段与
CLI `wiki plan/generate` 统一走它（§7.3 挂接点）。

### 14.2 页面类型与规划（`domain/wiki.py`、`generate/plan.py`）

- `PageType` 新增 `FLOW_DETAIL = "flow_detail"`、`CONCEPT = "concept"`；
  `ARCHITECTURE` 已存在，不新增；
- `CoveragePlanner.plan(facts, existing_deps=None, module_map=None)`：
  `module_map` 为 None 时内部 `build_module_map(facts)`（保证三调用点行为一致）；
- `_module_tasks` 改从 ModuleMap entries 取分组（含拆分子模块键）；排序权重规则不变；
- 新增 `_flow_detail_tasks`：入口候选按 `_reachable_calls` 降序，取可达数 > 0 的前 15
  （`_FLOW_DETAIL_LIMIT`；候选不足 5 个时全取），`page_id = flow-detail/<stem>`，
  subject 沿用 `path::name`，C3；与原 flow 页并存（flow 页保留覆盖统计职责，
  flow-detail 承担结构化流程叙述，内容规则随 S38 图校验一起落地）；
